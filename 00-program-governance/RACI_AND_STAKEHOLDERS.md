# RACI and Stakeholder Operating Model

## 1. Role definitions

| Role | Primary accountability |
|---|---|
| Executive Sponsor | Removes organizational blockers, approves gates and budget, protects strategic priority |
| AI Transformation Lead | Coordinates the program, translates business needs into workstreams, reports value and risk |
| R&D Owner | Owns formulations, experiments, technical requirements, and R&D knowledge capture |
| Production Owner | Owns process context, line access, operator participation, and practical implementation |
| Quality Owner | Owns quality definitions, release logic, defect severity, complaints, and validation |
| Packaging / Inspection Owner | Owns ELSIS or inspection-system data, defect labels, operator decisions, and packaging workflow |
| IT / Security Owner | Approves architecture, access, hosting, identity, logging, backup, and cyber controls |
| Finance / Controlling Owner | Validates baseline costs, benefits, assumptions, and ROI calculations |
| Data Owner | Authorizes use, defines meaning, quality, retention, and access for a specific source |
| Employee Representative | Reviews privacy, transparency, and employee-impact concerns where applicable |
| External Partner | Provides specialist implementation or research support under approved contracts and controls |

## 3. Stakeholder messages

| Stakeholder | Main concern | Program message |
|---|---|---|
| Managing Director | Competitiveness, risk, cost, growth | Start small, protect know-how, prove measurable value before scaling |
| Production Management | Stability, workload, disruption | Read-only first; the pilot helps explain recurring problems and does not control machines |
| Operators | Surveillance, replacement, extra documentation | The system supports troubleshooting and captures expertise; it is not an employee-ranking tool |
| Quality | Traceability, compliance, complaints | Faster evidence retrieval, repeat-defect prevention, and better roll-level visibility |
| R&D | Technical depth, confidentiality, experiment learning | Preserve failed and successful experiments and accelerate formulation learning |
| IT | Security, maintainability, shadow tools | Approved architecture, least privilege, audit logs, controlled data flows |
| Finance | Credible value and bounded spending | Two-stage approval, validated baseline, auditable assumptions, measurable outcomes |
| Sales / Customer Service | Faster answers and customer trust | Better access to approved product, quality, complaint, and certification evidence |
| Works Council / Employee Representatives | Privacy and employee impact | Data minimization, transparency, no hidden performance scoring, formal review where required |

## 4. Meeting structure

### Weekly working meeting

- progress against work breakdown;
- data access and quality blockers;
- decisions needed;
- risks and mitigations;
- next seven days.

### Biweekly sponsor update

- one-page status;
- value evidence;
- unresolved cross-functional blockers;
- scope or budget changes;
- gate readiness.

### Gate review

Every gate decision must record:

- evidence reviewed;
- approved scope;
- approved budget;
- accepted risks;
- named owners;
- decision: go, revise, pause, or stop.
